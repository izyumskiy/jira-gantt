# Архитектурное ревью модулей

Дата ревью: 10 сентября 2026 года.

## Область проверки

Проверены переносимые модули `people-analytics` и `project-planning`, их публичные контракты, вычислительное ядро, адаптеры текущего Chrome-расширения и контрактные тесты.

## Архитектурные границы

- `ohmygant-modules/src/**` — единственный источник бизнес-формул. Код этого слоя детерминирован и не обращается к DOM, Chrome API, сети или локальному хранилищу.
- `src/modules/**` — тонкий слой совместимости текущего расширения; расчётная логика в нём не дублируется.
- `src/js/**` — инфраструктурные адаптеры Jira, Tempo, Confluence, GitLab, IndexedDB и UI.
- Все внешние зависимости входят в модули через read-only порты. Токены и браузерные разрешения не являются частью предметной модели.

## Исправленные замечания

### Критические

1. Удалено неявное сопоставление Jira-ключей с конкретными репозиториями. Репозиторий участвует в анализе только при наличии подтверждённой ссылки в Jira или Confluence.
2. Удалена отдельная ветка расчёта для одного заранее известного технологического сценария. Технические работы теперь формируются общими правилами по намерению из требований и фактам из манифестов репозитория.
3. Удалён фиксированный GitLab-домен. Разрешение Chrome запрашивается только для доменов явно связанных репозиториев.
4. Версия `project-planning` повышена до `2.0.0`, поскольку из технического профиля удалены поля прежнего специального сценария.

### Высокие

1. В Jira-адаптер добавлена загрузка remote links. Без этого общий механизм обнаружения репозиториев терял подтверждённые связи, хранящиеся не в описании задачи.
2. Тестовые данные обезличены: в них нет идентификаторов, названий, доменов и репозиториев ранее анализировавшихся инициатив.
3. Ядро аналитики сотрудников приведено из минифицированного вида к читаемому формату без изменения формул.
4. Политика базовой оценки, объяснение P50/P80/P90 и последовательный backtest вынесены из крупных расчётных файлов в отдельные чистые модули.
5. Backtest инициатив исключает look-ahead: обучающая выборка содержит только данные, завершённые до старта проверяемой инициативы.
6. Монолитный анализ разделён на композицию источников, классификацию, извлечение и reconciliation требований, системный анализ, оценивание и подбор исполнителей. `analysis.js` оставлен оркестратором публичного сценария.

## Инварианты для следующих изменений

1. Нельзя выбирать репозиторий по префиксу ключа, названию Jira-проекта, команде или слову в заголовке.
2. Нельзя добавлять оценку, коэффициент или набор работ для конкретной инициативы, технологии либо версии. Правило должно опираться на универсальный тип изменения и подтверждённые факты.
3. Названия технологий допустимы только как результат распознавания стека или классификации требований; они не задают отдельную формулу оценки.
4. Если технический контур не подтверждён, расчёт продолжается по Jira/Confluence и явно снижает полноту прогноза.
5. Приоритет `BAZA` передаётся как бизнес-признак `isBaza`; он не связан с конкретными ключами задач.
6. UI не должен содержать расчётных формул, а gateway — изменять Jira, Tempo, Confluence или GitLab.

## Оставшийся технический долг

- Словари классификации и базовые эвристики являются общими, но пока находятся в коде. Следующий безопасный шаг — вынести их в версионируемую конфигурацию модуля без продуктовых значений по умолчанию.
- Нужны накопительные backtest-наборы на обезличенных завершённых инициативах. Они должны измерять ошибку прогноза, а не закреплять ручной ожидаемый результат отдельного кейса.
- Для контролируемого развития формул нужен версионируемый идентификатор модели в результатах расчёта и журнал сравнения качества версий на одном backtest-наборе.

## Критерии приёмки архитектуры

- пакетные, контрактные и браузерные self-test проходят;
- в переносимом ядре отсутствуют сетевые и браузерные API;
- произвольный Jira-ключ без ссылок не подключает репозиторий;
- явная GitLab-ссылка работает для произвольного домена;
- сумма декомпозиции совпадает с итоговой базовой оценкой;
- уже учтённые задачи Jira не получают повторные часы из технического анализа.
