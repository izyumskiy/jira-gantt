# ТЗ: ракурс «Эпик — история», проекты и заметки в комментариях Jira

Плагин Jira OhMyGant, версия на момент ТЗ — 1.12.0.

## 1. Цель

Менеджеры отчитываются о статусе в Excel: строка на проект, внутри эпики и пользовательские
истории (User Story) со статусами, заметки рядом. Плагин показывает эпики и задачи, но не
показывает истории и не умеет группировать эпики в проекты. Поэтому таблица живёт отдельно
и статусы в неё переписываются вручную.

Нужно, чтобы эта таблица собиралась в плагине сама:
- **проект → эпик → история** с приоритетами и статусами из Jira;
- диаграмма Ганта по историям — такая же, как на других ракурсах;
- заметки менеджера к проекту и к истории, которые хранятся в комментариях Jira и видны всем.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Что такое проект | Фиктивная сущность: в Jira её нет. Эпики произвольно объединяются в проекты |
| Где хранится принадлежность эпика к проекту | В комментарии к эпику: `[omg project] Название проекта`. Действует последний такой комментарий |
| Можно ли сменить проект из плагина | Да. Плагин публикует новый комментарий `[omg project]` в эпик |
| Уровни заметок | Проект и история. Отдельной заметки у эпика нет |
| Где хранятся заметки | В комментариях Jira с кодовым словом `[omg comment]`: к истории — в самой истории, к проекту — в эпиках проекта (Р4) |
| Как задачи связаны с историями | Связью Jira «relates to» |
| Приоритет | Поле «Приоритет» Jira. Выводятся пиктограммы приоритетов, проекты сортируются по приоритету |
| Шкала времени | Та же, что на других ракурсах: секции спринтов, «Бэклог», задачи вне спринта (Д1). Недели месяца не вводим |
| Ручные вехи («Публикация», «Полная готовность») | Не делаем |
| Истории и прогноз | Истории показываются как структура, но по-прежнему не считаются задачами в количестве и прогнозе («Типы задач, не учитываемые в подсчётах») |

## 3. Термины

| Термин | Определение |
|---|---|
| Проект | Группа эпиков с общим названием. Живёт только в комментариях `[omg project]` |
| История | Задача Jira типа из настройки «Типы историй» (по умолчанию `User Story`) в выбранном эпике |
| Задача истории | Задача, связанная с историей связью «relates to» (в любую сторону) |
| Метка проекта | Комментарий к эпику, который начинается с `[omg project]` |
| Заметка | Комментарий, который начинается с `[omg comment]` |
| Приоритет проекта | Самый высокий приоритет среди незавершённых эпиков проекта |

Кодовые слова ищутся в начале комментария (после пробелов), без учёта регистра:
`[OMG Project]` и `[omg project]` равнозначны. Комментарии, написанные вручную в Jira в том же
формате, плагин понимает так же, как свои.

## Функциональные блоки

### Р1. Вкладки-ракурсы: пиктограммы одного стиля

**Назначение.** Три ракурса диаграммы Ганта — одна семья функций. Визуально они должны
отличаться от «Поиска», «Сводки», «Команды» и «Настроек».

- «По эпикам» и «По людям» становятся пиктограммами. Добавляется третья — **«Эпик — история»**.
- Три пиктограммы стоят рядом **общей группой**: одна подложка, один цвет, разделитель
  с соседними вкладками. Активная — подсвечена внутри группы.
- Пиктограммы (единый набор, один стиль линий):

| Ракурс | Пиктограмма | Подсказка |
|---|---|---|
| По эпикам | Горизонтальные полосы диаграммы Ганта | «По эпикам» |
| По людям | Силуэт человека с полосами | «По людям» |
| Эпик — история | Дерево из трёх уровней с полосами | «Эпик — история» |

- Подпись — во всплывающей подсказке и в `aria-label`, переводится вместе с языком.
- «Команда» остаётся текстовой, «Поиск», «Сводка», «Настройки» — как сейчас.

**Приёмка:** три пиктограммы в одной группе, по стилю отличаются от остальных вкладок; каждая
открывает свой ракурс; подсказки на русском и английском.

### Р2. Данные: приоритеты, связи, комментарии

**Новые данные при синхронизации:**

| Что | Откуда | Для чего |
|---|---|---|
| Приоритет эпиков, историй и задач | Поле `priority`: название, id, адрес пиктограммы | Р6 |
| Порядок приоритетов | `/rest/api/2/priority` (порядок в ответе — от высшего к низшему) | Сортировка |
| Связи задач | Поле `issuelinks` | Р5: задачи истории |
| Комментарии эпиков и историй | Поле `comment` отдельным лёгким запросом только по эпикам и историям | Р3, Р4 |

- Комментарии задач не запрашиваются: их много, а кодовые слова там не нужны.
- Если Jira отдала не все комментарии задачи (`total` больше числа полученных), догружаются
  остальные через `/rest/api/2/issue/{key}/comment`.
- Из комментариев сохраняются только разобранные метки проекта и заметки. Остальные комментарии
  в базу не пишутся.
- Новый комментарий меняет поле «Обновлено» у задачи, поэтому «Обновить» подхватывает новые
  метки и заметки без полной перезагрузки.
- Всё пишется в общей транзакции синхронизации (А2). Новые поля — повышение `ISSUE_SCHEMA`,
  одна автоматическая полная перезагрузка.

**Настройки** (карточка «Поля»):

| Настройка | По умолчанию |
|---|---|
| Типы историй | `User Story` (через запятую) |
| Связь задачи с историей | `Relates` (название типа связи Jira; направление не важно) |

**Приёмка:** после «Обновить» у историй есть приоритет, связанные задачи и разобранные заметки;
комментарий, добавленный в Jira вручную, появляется после следующего «Обновить».

### Р3. Проекты

**Разбор.** Для каждого эпика берётся **последний по дате** комментарий `[omg project]`.
Название проекта — текст после кодового слова в первой строке, без пробелов по краям.

| Случай | Результат |
|---|---|
| Меток нет | Эпик в группе «Без проекта» |
| Последняя метка с пустым названием | Эпик выведен из проекта → «Без проекта» |
| Названия отличаются регистром или пробелами | Один проект: сравнение без учёта регистра и лишних пробелов; показывается написание из самой свежей метки |

**Смена проекта из плагина.** На строке эпика — кнопка «Проект…»:
- выпадающий список существующих проектов, поле «Новый проект» и пункт «Без проекта»;
- после выбора плагин публикует в эпик комментарий `[omg project] Название` (для «Без
  проекта» — `[omg project]` без названия) и сразу переносит эпик локально;
- при ошибке публикации эпик остаётся на месте, сообщение — в строке статуса.

**Переименование проекта.** На строке проекта — «Переименовать…». Плагин публикует новую метку
во **все** эпики проекта. Перед этим — подтверждение с числом эпиков: каждый комментарий уходит
письмом наблюдателям эпика.

**Приёмка:**
- эпик с двумя метками попадает в проект из последней;
- смена проекта из плагина видна в Jira комментарием и сразу — на диаграмме;
- «Проект» и «ПРОЕКТ » — один проект.

### Р4. Заметки `[omg comment]`

**Формат.** Первая строка — `[omg comment]`, дальше свободный текст. Автор и дата берутся из
комментария. Действует последняя заметка; предыдущие — история.

**Заметка истории** — комментарий `[omg comment]` в самой истории.

**Заметка проекта.** У проекта нет своей задачи в Jira, поэтому:
- **читается** последняя заметка `[omg comment]` среди **всех эпиков проекта**; история
  заметок проекта — все такие комментарии его эпиков по дате, с указанием эпика;
- **пишется** в эпик проекта с наивысшим приоритетом (при равенстве — с меньшим ключом);
- при переносе эпика в другой проект его заметки уходят вместе с ним.

**Отображение** (на ракурсе «Эпик — история»):
- **строка заметки** под строкой проекта и под строкой истории: первые две строки текста,
  автор, дата, полный текст при наведении;
- кнопки ✎ «Изменить» и «История (N)»;
- нет заметки — бледное «Заметки нет · добавить»;
- заметка старше 14 дней (настройка) помечается «заметке N дн.»;
- галочка «Заметки» на панели ракурса скрывает и показывает строки заметок.

**Правка.** ✎ открывает форму, заполненную текстом последней заметки. «Сохранить в Jira»
публикует новый комментарий `[omg comment]`, старая заметка остаётся в истории. Под кнопкой —
предупреждение, что наблюдатели получат письмо.

**Приёмка:**
- заметка, добавленная в плагине, видна в Jira комментарием, а в плагине — сразу;
- заметка проекта, написанная вручную в любом его эпике, показывается как заметка проекта;
- история заметок проекта собирает комментарии всех его эпиков по дате.

### Р5. Ракурс «Эпик — история»

**Структура строк:**

```
▾ Проект        [приоритет] Название · эпиков N · историй M · итог по секциям
    заметка проекта
  ▾ Эпик        [приоритет] Ключ · Epic Name · статус · кнопка «Проект…» · 💬
    ▾ История   [приоритет] Ключ · название · статус · полосы по секциям
        заметка истории
      Задачи вне историй — одной строкой «Без истории»
▾ Без проекта
```

**Полосы — та же механика Ганта, что на других ракурсах:**
- секции спринтов, колонка «Бэклог», задачи вне спринта в работе — в текущей секции (Д1);
- полоса истории — её задачи (Р2) по спринтам, с долей готового; клик — список задач;
- если у истории нет задач, но у неё самой есть спринт, — полоса по спринту истории;
- у эпика — итог по его историям и задачам без истории, веха срока исполнения;
- у проекта — итог по его эпикам, веха — ближайший срок исполнения его эпиков;
- 💬 комментарии эпика, подсказки, свёрнутость по умолчанию и «Развернуть всё» / «Свернуть всё»
  — как на «По эпикам».

**Сортировка:**
- проекты — по приоритету проекта, затем по названию; «Без проекта» — внизу;
- эпики в проекте — по приоритету, затем по статусу (как на «По эпикам»), затем по ключу;
- истории в эпике — по приоритету, затем по ключу (по номеру).

**Подсчёты:**
- задача, связанная с несколькими историями, показывается в каждой из них, но в итогах эпика
  и проекта считается один раз;
- в итогах эпика и проекта, как и везде, не считаются сами истории и отменённые задачи.

**Какие эпики:** выбранные на «Поиске» (со снятой галочкой — скрыты), с фильтрами «Поиска», как
на «По эпикам».

**Приёмка:**
- проекты, эпики и истории идут в порядке приоритетов, у каждой строки — пиктограмма приоритета;
- полоса истории строится по связанным задачам; задача без связи — в «Без истории»;
- задача, связанная с двумя историями, видна в обеих, а в итоге эпика — один раз.

### Р6. Приоритеты Jira

- У проекта, эпика и истории перед названием — **пиктограмма приоритета** из Jira, название
  приоритета — в подсказке.
- Порядок приоритетов — из Jira (Р2). Нет приоритета — ниже самого низкого.
- Если пиктограммы Jira не загружаются (закрыты для расширения), вместо них — цветной кружок
  по месту в порядке приоритетов (от красного к серому) с названием в подсказке.

**Приёмка:** пиктограммы совпадают с Jira; при недоступных пиктограммах видны цветные кружки.

## 4. Нефункциональные требования

- **Приватность.** Плагин пишет в Jira только по явному действию пользователя: смена проекта,
  переименование, заметка. Больше в Jira ничего не отправляется.
- **Уведомления.** Каждый комментарий `[omg …]` Jira рассылает наблюдателям задачи. Форма заметки,
  смена проекта и переименование об этом предупреждают.
- **Права.** Для записи нужно право «Добавлять комментарии» в проекте Jira. Нет права — понятное
  сообщение, данные в плагине не меняются.
- **Производительность.** Запрос комментариев — только по эпикам и историям, пачками по 50.
  Построение ракурса — не дольше «По эпикам» на тех же данных.
- **Архитектура.** Разбор кодовых слов, группировка в проекты и итоги — в модуле расчётов без
  интерфейса (как А1), чтобы их проверял селфтест.
- **Язык.** Все тексты — в словаре ru/en. Кодовые слова `[omg project]` и `[omg comment]`
  не переводятся.
- **Тесты.** Селфтест: разбор меток (последняя, пустая, регистр), заметки проекта по нескольким
  эпикам, задачи в нескольких историях, сортировка по приоритетам, «Без проекта», «Без истории».
- **Документация.** README, INSTALL и инструкция для менеджеров.

## 5. Вне рамок

- Ручные вехи без задачи в Jira («Публикация», «Полная готовность»).
- Шкала по неделям месяца.
- Заметки на уровне эпика и задачи.
- Удаление и правка опубликованных комментариев: только новый комментарий.
- Проекты и заметки на «По эпикам», «По людям» и в «Сводке».

## 6. Порядок работ

| Этап | Блоки | Результат |
|---|---|---|
| 1 | Р1 | Пиктограммы ракурсов одной группой |
| 2 | Р2, Р6 | Приоритеты, связи, комментарии в данных; пиктограммы приоритетов |
| 3 | Р3, Р5 | Ракурс «Эпик — история» с проектами, сортировкой и Гантом |
| 4 | Р4 | Заметки проекта и истории: показ, история, правка |

Каждый этап — отдельный релиз с повышением версии.

## 7. Открытые вопросы

1. **Цвет оценки в заметке** (зелёный / жёлтый / красный), как в наброске. Если нужен — формат,
   например `[omg comment] [жёлтый]`.
2. **Эпик для записи заметки проекта** — эпик с наивысшим приоритетом. Если менеджеру удобнее
   выбрать «главный» эпик проекта вручную, это ещё одна метка.
3. **Задачи истории из невыбранных эпиков.** Связь «relates to» может вести в задачу чужого эпика.
   Сейчас такие задачи показываются, только если они есть в выгрузке («Прочие»); иначе не видны.
