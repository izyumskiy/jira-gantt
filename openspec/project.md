# Проект — Jira OhMyGant

## Что это
Расширение Chrome (MV3) для локальной Jira Server 9.x: диаграммы Ганта по эпикам, людям и историям,
«Сводка», прогноз сроков по потоку, Control Chart по доскам. Без сервера: данные — в IndexedDB
расширения, настройки — в `chrome.storage.local`.

## Стек и конвенции
- Чистые ES-модули без сборки: `src/js/` (Гант и расчёты), `src/cc/` (Control Chart), `src/llm/`
  (клиент LLM и промпты). Модули расчётов — без интерфейса, их проверяет селфтест.
- Одна база `jiragantt`: схема и версия — только в `src/js/db.js`.
- Тексты интерфейса — в словаре ru/en (`src/js/dict.js`), комментарии в коде — на русском.
- Проверка: `dev/selftest.html` (логика, без Jira и без сети; `fetch` и `chrome.*` подменяются) и
  `dev/apptest.html` (интерфейс как веб-страница). CI нет — селфтест обязателен перед коммитом.
- Каждая история — отдельный релиз с повышением версии в `manifest.json`, README и `RELEASE_NOTES.md`.
- Ponytail: наименьшее полное изменение поверх существующего кода; нетривиальная логика — с проверкой
  в селфтесте; известное упрощение — комментарием `shortcut: <ограничение>, <когда менять>`.

## Как устроен этот openspec/
- `changes/<id>/` — изменение-история: `proposal.md` (зачем, что, влияние), `design.md` (технические
  решения, если они есть), `specs/<capability>/spec.md` (дельта требований со сценариями), `tasks.md`
  (шаги реализации).
- `specs/` — нормативное состояние возможностей; наполняется при архивации изменения после
  реализации.

## Источник решений
`docs/TZ-llm.md` — ТЗ «AI-анализ срока эпика» (блоки А1–А8): обоснования и решения. Нормативные
требования — в дельтах `specs/`; ТЗ остаётся рассуждением, на него ссылаются `design.md`. При
расхождении правится один источник.
