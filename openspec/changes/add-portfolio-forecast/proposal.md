# Change: add-portfolio-forecast (US-4. Прогноз портфеля с бизнес-тестом)

## Why
Текущий прогноз считает эпик сам по себе, с постоянной долей потока, и только разработку. На деле
эпики делят команды: когда один заканчивается, люди переходят на другие; перегруженные люди тормозят
соседние эпики; после разработки идёт приёмка.

**История.** Как менеджер, я хочу видеть срок готовности эпика (95-й перцентиль) с учётом доли потока
команд, освобождения людей от других эпиков, блокировок и приёмки заказчика.

## What Changes
- Расчёт всех выбранных незавершённых эпиков вместе, неделя за неделей, 10 000 прогонов, с зерном.
- Одна выбранная неделя истории на команду; эпики команды делят её по долям потока; доля закончившего
  эпика делится между оставшимися эпиками команды.
- Поток приводится к рабочим дням по календарю (US-1); остаток и история — без заглушек (US-2).
- Блокировки — вход расчёта (их даёт US-8): задержка из перегруза людей, в доле прогонов по
  уверенности.
- К концу разработки прибавляется приёмка заказчика (US-3) в рабочих днях.
- Выход: P50/P85/P95 разработки и готовности, шанс успеть к сроку, узкое место, вклады освобождения
  и блокировок.

Основание — ТЗ, блок А2.

## Impact
- **Код:** новый `src/js/portfolio.js` (расчёт без интерфейса) поверх `flow.js`; вызов через
  `forecast.worker.js`.
- **Данные:** не меняются.
- **Производительность:** портфель из 50 эпиков — до 5 секунд в фоновом потоке.
