# Design — add-portfolio-forecast

Обоснования — `docs/TZ-llm.md`, блок А2.

## Модель прогона
- Входы эпика: остаток по командам (как `forecastForTeams`: остаток делится по вкладу команд), доля
  потока `forecastShare`, история команды — те же недели, что у текущего прогноза.
- Неделя `k`: на команду выбирается одна неделя истории `i` (с возвратом). Поток недели:
  `perWeek[i] × 5 / wd(i) × wd(k) / 5`, где `wd` — рабочие дни недели по календарю.
- Эпик получает `поток × доля`; доли закончивших эпиков команды перераспределяются пропорционально
  оставшимся (работа вне портфеля не меняется).
- Конец разработки эпика — неделя, когда он закончил во всех командах; дата — последний рабочий день
  этой недели.
- Блокировка `{люди, секции, задержка_нед, уверенность}` прибавляет задержку к концу разработки с
  вероятностью `уверенность`. Задержка = перегруз людей в секциях, вызванный блокером, в часах /
  (`5 × часов в дне`); по людям — максимум, по блокировкам — сумма. Считает US-8, здесь — только вход.
- Готовность = конец разработки + срок приёмки (выборка US-3 × поправка) рабочих дней.

## Вклады влияния
Два дополнительных расчёта по 5000 прогонов: без перераспределения и блокировок; с перераспределением,
без блокировок. Разности P95 — вклады освобождения и блокировок.

shortcut: эпики без истории потока не участвуют и не получают освобождённую долю — когда появится
плановая ёмкость эпиков, принимать их в расчёт.
