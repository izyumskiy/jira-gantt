# Change: add-work-calendar (US-1. Производственный календарь)

## Why
Срок готовности считается в рабочих днях: поток команды в праздничную неделю меньше, приёмка заказчика
идёт по рабочим дням, ёмкость человека в спринте с праздниками ниже. Сейчас плагин знает только пн–пт
и фиксированную «Длительность спринта».

**История.** Как менеджер, я хочу, чтобы плагин считал рабочие дни по производственному календарю РФ,
чтобы прогнозы и загрузка учитывали праздники и переносы.

## What Changes
- Календарь из репозитория d10xa/holidays-calendar: один файл `json/calendar.json` на все годы.
- «Настройки → Производственный календарь»: состояние, «Обновить», ручные рабочие и нерабочие дни.
- Модуль `src/js/workcal.js`: рабочий ли день, рабочих дней между датами, дата через N рабочих дней.
- Ёмкость человека в секции на «По людям» — рабочие дни секции по календарю × «Часов в рабочем дне»,
  когда календарь загружен.

Затрагиваемая capability: `work-calendar`. Основание — ТЗ, блок А8.

## Impact
- **Код:** новый `src/js/workcal.js`; `src/js/agg.js` (`sprintCapacity` — по секции); `src/app.html`,
  `src/js/app.js` (блок настроек); `src/js/settings.js` (ручные дни); `src/js/dict.js`.
- **Данные:** `meta.calendar` — загруженный файл и дата загрузки. Схема базы не меняется.
- **Сеть:** `raw.githubusercontent.com` — разрешение на домен запрашивается кнопкой «Обновить».
- **Совместимость:** без загруженного календаря — пн–пт и «Длительность спринта», как сейчас.
