# Change: add-plan-forecast (US-11. Разработка от плана спринтов; задачи сопровождения)

## Why
Разработка в AI-анализе считалась только по темпу закрытий: план спринтов не учитывался, и срок
расходился с планом на месяцы. Остаток делился между командами по прошлому вкладу, а не по
исполнителям — команда с одной задачей сопровождения становилась узким местом. Окно заглушек
прибавлялось к разработке целиком, хотя заглушки стоят в спринтах параллельно с ней.

**История.** Как менеджер, я хочу, чтобы срок разработки опирался на план спринтов с риском переносов
из истории, чтобы задачи сопровождения не тормозили срок, а бизнес-тест по заглушкам не считался дважды.

## What Changes
- Задачи разработки в спринтах с датами — по плану: конец спринта + переносы из истории. Переносы — по
  группам «эпик × команда × спринт»: задачи одной команды в одном спринте переезжают вместе.
- Задачи без спринта — по темпу закрытий, как раньше. Конец разработки — позднее из двух + блокировки.
- Остаток по командам — по исполнителям; без исполнителя — по прошлому вкладу.
- Задачи сопровождения (настройка «Признаки задач сопровождения», по умолчанию «поддержка,
  сопровождение»; LLM тоже может назвать) — не разработка и не бизнес-тест.
- Бизнес-тест без истории приёмок — хвост плана заглушек после разработки; кончаются в одном спринте —
  БТ внутри него.
- Блокировка задерживает эпик только на вытесненную работу самого эпика.

## Impact
- **Код:** `aiAnalysis.js` (`buildInputs`, `slipPools`, `stubWindow`), `portfolio.js` (план в прогоне),
  `adjustments.js` (`support_tasks`, формула блокировки), объяснение, настройки, словарь.
