# Change: add-llm-adjustments (US-8. Поправки LLM: блокировки, заглушки, приёмка)

## Why
По статусам и истории не видно, что люди эпика перегружены другими эпиками, какие ещё задачи — это
заглушки и что заказчик в отпуске. Это видно по загрузке и переписке — работа для LLM.

**История.** Как менеджер, я хочу, чтобы AI-анализ по загрузке людей в спринтах находил блокировки, по
задачам и переписке — заглушки и обстоятельства приёмки, и учитывал их в сроке.

## What Changes
- Запрос к LLM при «Новом анализе»: эпик, задачи с признаком заглушки, истории, 30 последних
  комментариев, загрузка людей эпика по секциям (ёмкость по календарю, разбивка по эпикам, перегруз),
  статистика заказчика и окно заглушек, эпики портфеля, праздники.
- Ответ: блокировки, дополнительные заглушки, коэффициент к приёмке, отсутствие заказчика, наблюдения.
- Проверка ответа кодом и границы; один повтор; иначе — без поправок с пометкой.
- «Не учитывать» у поправки действует и в следующих анализах.
- `personLoad` дополнительно отдаёт суммы по эпикам.

Основание — ТЗ, блок А4.

## Impact
- **Код:** `src/llm/adjustments.js` (входы, промпт, проверка), `agg.personLoad` (разбивка по эпикам),
  `aiAnalysis.js` (применение), `jira.js` (комментарии эпика и историй при запуске).
