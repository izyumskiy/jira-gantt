# Jira OhMyGant — установка и настройка

Расширение для Google Chrome, работает с локальной Jira Server 9.x. Ничего не
устанавливает на сервер Jira и не требует прав администратора: только чтение
через REST API от вашего имени.

---

## Часть 1. Установка расширения

1. **Получите код.** Либо `git clone https://github.com/izyumskiy/jira-gantt`,
   либо на странице репозитория **Code → Download ZIP** и распакуйте архив.
   Папку никуда не перемещайте после установки — Chrome загружает расширение
   прямо из неё.
2. Откройте в Chrome адрес `chrome://extensions`.
3. Включите переключатель **Режим разработчика** (правый верхний угол).
4. Нажмите **Загрузить распакованное расширение** и укажите папку проекта
   (ту, где лежит `manifest.json`).
5. В списке появится **Jira OhMyGant** с синей иконкой. Нажмите на значок-пазл
   на панели Chrome и закрепите иконку расширения, чтобы она была под рукой.
6. Кликните по иконке — откроется отдельная вкладка приложения. При первом
   запуске оно само откроет вкладку **Настройки**.

> Обновление: после `git pull` (или распаковки новой версии в ту же папку)
> нажмите на `chrome://extensions` кнопку ⟳ **Обновить** у расширения и
> перезагрузите вкладку приложения. Данные и настройки при этом сохраняются.

## Часть 2. Подключение к Jira (вкладка «Настройки»)

### Шаг 1. Адрес Jira
В поле **Адрес Jira** введите корень вашей Jira, например
`https://jira.company.local` — без `/browse/…` и без слэша на конце.

### Шаг 2. Разрешение на домен
Нажмите **Разрешить доступ к домену**. Chrome покажет запрос на доступ к
этому сайту — подтвердите. Без этого шага расширение не сможет обращаться к
Jira (домен не зашит в манифест, права выдаются именно вашему серверу).

### Шаг 3. Проверка подключения
Нажмите **Проверить подключение**. Должно появиться «Подключено: Ваше имя».

Расширение использует cookie вашей текущей сессии: если вы залогинены в Jira
в этом же Chrome, вводить пароль не нужно.

Если вместо имени пришла ошибка авторизации:
- откройте Jira в соседней вкладке и войдите, затем повторите проверку; или
- создайте в Jira **Personal Access Token** (Профиль → Personal Access Tokens
  → Create token), вставьте его в поле **Personal Access Token** и повторите.
  Токен используется только когда cookie не сработали, хранится локально в
  Chrome.

### Шаг 4. Определить поля Jira
Нажмите **Определить поля Jira**. Расширение найдёт номера кастомных полей
вашей инсталляции: Epic Link, Epic Name, Sprint, Story Points, Planned Start /
Planned End. Результат появится в строке рядом с кнопкой, например
`Epic Link: customfield_10100 · Sprint: customfield_10101 · …`.

Если какое-то из полей показано прочерком — см. раздел «Если что-то не так».

### Шаг 5. Плановые даты и люди (при необходимости)
- **Поле «Плановое начало» / «Плановое завершение»** — выпадающие списки со
  всеми полями типа «дата» вашей Jira. Обычно автоопределение уже выбрало
  верные; меняйте, только если в Jira есть несколько одноимённых полей.
- **Поле «Исполнитель эпика» / «Постановщик эпика»** — из каких полей брать
  людей для эпиков на «Поиске эпиков». По умолчанию стандартные Assignee и
  Reporter; можно выбрать любое кастомное поле-пользователя (например,
  «Владелец продукта»).

### Шаг 6. Оценка
- **Что считать оценкой** — Original Estimate (часы), Remaining Estimate или
  Story Points. Выберите то, чем реально пользуется команда.
- **Часов в рабочем дне** — для перевода часов в дни на диаграммах (8 → «1д»).

### Шаг 7. Статусы «Готово»
Расширение уже считает завершёнными статусы Готово, Закрыто, Done, Closed,
Resolved, On Prod, Cancel и их варианты. Если в вашем потоке есть другие
завершающие статусы (например, «Sign off»), впишите их через запятую в поле
**Статусы, означающие «Готово»**.

### Шаг 8. Доска (спринты)
Нажмите **Загрузить список досок** и выберите доску, на которой заведены ваши
спринты. С неё берутся даты спринтов и будущие спринты без задач. Если досок
несколько (разные команды), выберите основную — спринты остальных досок всё
равно подтянутся из задач.

### Шаг 9. Информационные системы (для вкладки «Команда»)
В поле **Информационные системы** перечислите системы по одной в строке —
это справочник, из которого на вкладке «Команда» выбираются системы каждого
сотрудника.

### Шаг 9а. Предварительная конфигурация (по желанию)
Если есть готовый JSON-конфиг (адрес Jira, поля, справочник систем, список
эпиков, сотрудники с ролями и системами), в карточке **Предварительная конфигурация**
выберите файл и нажмите **Загрузить и применить**: адрес Jira из файла
сохранится, Chrome запросит разрешение на домен, подключение проверится по
текущей сессии (в журнале появится «Подключено: ваше имя»), **локальная база
очистится полностью** (эпики, задачи, спринты и профили сотрудников — конфиг
становится единственным источником), затем поля и системы сохранятся,
эпики найдутся в Jira, добавятся в «Поиск» и выгрузятся, профили сотрудников
заполнятся. Ход применения виден в журнале под кнопками. Кнопка **Экспорт
конфигурации** скачивает такой же JSON с текущим состоянием — удобно
перенести настройку на другой компьютер.

### Шаг 10. Сохранить
Нажмите **Сохранить настройки**. Кнопки «Проверить подключение» и
«Определить поля» сохраняют форму сами, но после правки полей на шагах 5–9
нажать «Сохранить настройки» нужно.

## Часть 3. Первая выгрузка

1. Перейдите на вкладку **Поиск эпиков**.
2. Введите часть названия эпика или его ключ (`PRJ-123`) и нажмите **Найти**.
   Пустой запрос выдаёт последние изменённые эпики.
3. Отметьте галочками нужные эпики (можно **Выбрать все**).
4. Нажмите **Сохранить выбор**. Начнётся загрузка: задачи эпиков, статусы,
   спринты, задачи исполнителей вне выбранных эпиков. Прогресс показывается
   строкой под шапкой; по окончании — «Готово».
5. Откройте **По эпикам** и **По людям**.

Дальше обновляйте данные кнопкой **Обновить данные** в шапке — она тянет
только изменившееся с прошлого раза. **Скачать заново** — полная перезагрузка
(например, после смены поля оценки или удаления задач в Jira).

## Часть 4. Что где

| Вкладка | Что делает |
|---|---|
| **Поиск эпиков** | Список сохранённых и найденных эпиков: статус, даты, метки, исполнитель, постановщик. Клик по метке или имени фильтрует списки и Гант. Снятая галочка скрывает эпик с Ганта, «Сохранить выбор» удаляет неотмеченные из базы. Красная строка — срок ≤ 14 дней или просрочен. |
| **По эпикам** | Эпики → исполнители по временным секциям спринтов; фильтр по исполнителю эпика; колонка «Бэклог»; клик по полосе — список задач; ⚡ критический путь. |
| **По людям** | Исполнители по командам (доскам); жёлтая часть полосы — целевые эпики, серая — прочие; строка «Прочие»; роль и статус из профиля. |
| **Команда** | Роль, информационные системы и статус каждого сотрудника; хранится локально, сопоставляется по имени. |
| **Настройки** | Всё из части 2; кнопка «Очистить базу» удаляет выгрузку (профили людей остаются). |

Язык интерфейса переключается в шапке (Русский / English).

## Если что-то не так

**«Не удалось связаться с Jira»** — проверьте адрес (открывается ли он в
браузере) и что на шаге 2 выдано разрешение на домен. Для самоподписанного
сертификата откройте Jira во вкладке и примите предупреждение Chrome.

**«Jira не авторизовала запрос»** — сессия истекла: войдите в Jira заново или
укажите PAT (шаг 3).

**Не найдено поле «Epic Link»** — в Jira не установлен Jira Software (Agile)
или у вашего пользователя нет прав на проекты. Нажмите «Определить поля Jira»
ещё раз после входа под нужным пользователем.

**Плановые даты пустые** — откройте «Настройки» и посмотрите, какие поля
выбраны в списках «Плановое начало / завершение»; выберите нужные и нажмите
«Обновить данные».

**Даты спринтов не обновились** — нажмите «Обновить данные»: спринты
перечитываются при каждом обновлении независимо от задач.

**Гант пустой, хотя эпики выбраны** — над диаграммой написано, что скрыто
галочками или фильтрами со страницы поиска; там же ссылка «снять фильтры».
Также проверьте, что у задач есть спринты: задачи без спринта попадают только
в «Бэклог».

**Хочу начать с чистого листа** — «Настройки» → «Очистить базу», затем
заново «Поиск эпиков» → «Сохранить выбор».
